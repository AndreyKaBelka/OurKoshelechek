# Грабли и что сработало

Читать при изменениях БД/API/финансовой модели и при отладке. Пополнять после каждой
новой грабли или правки от владельца: **симптом → причина → правило**.

## БД и миграции
- **`ON CONFLICT` без constraint** (`SQLSTATE 42P10` при пополнении цели).
  Причина: `INSERT … ON CONFLICT` по полям без уникального индекса + check-then-create до
  транзакции (гонка → дубли «Накоплений»). Правило: get-or-create = уникальный индекс +
  `INSERT … ON CONFLICT DO NOTHING` + `SELECT` в репозитории (`Category.GetOrCreate`).
  Но сначала спросить себя, нужна ли вообще эта запись.
- **FK violation при удалении категории** (`SQLSTATE 23503`,
  `transactions_category_id_fkey`). Правило: не `CASCADE` — отвязать транзакции
  (`SET category_id = NULL`), потом удалить. История дороже справочника.
- **Порядок истории внутри дня был случайным** — тайбрейк по UUIDv4. Правило: все id через
  `platform.NewID()` (UUIDv7).
- **Удалить значение enum в Postgres нельзя** — Down пересоздаёт тип
  (см. `20260923140000_transfers.sql`).
- **Гонка регистрации одинакового username** отдавала сырую ошибку БД. Правило:
  `23505` → sentinel в репозитории, сервис перехватывает.

## Авторизация
- **FK не проверяет групповую принадлежность.** `category_id`, `user_id` в долях/целях
  ссылаются на глобальные таблицы → можно подставить чужую категорию/пользователя.
  Правило: `requireGroupMember` / `GetByID(ctx, groupID, id)` для каждого id из инпута,
  **до** `RunInTx`.
- **`min: MEMBER` пускал MEMBER удалить OWNER.** Правило: если действие направлено на
  другого участника — сравнивать роли в сервисе (`actor.Role.AtLeast(target.Role)`).

## Код
- **`len()` по строке = байты**; на кириллице лимиты срабатывали вдвое раньше. Правило:
  `utf8.RuneCountInString`.
- **Литерал доменной структуры в mapper** обходил валидацию. Мёртвые `ToDomain*` удалены;
  новые — только через `New<Entity>`.
- **Дублирование логики ролей** (`domainRoleFromModel` vs `mapper.ToDomainGroupRole`) —
  одна функция маппинга на enum.

## Frontend
- **Общий dirty-state на несколько форм** («Сохранить доли» активировалась при
  редактировании цели). Правило: отдельное состояние изменений на каждую форму.
- **Тихий fallback на текущего пользователя** (`partner?.userId ?? currentUserId`) маскирует
  отсутствие партнёра и пишет неверного плательщика. Правило: отсутствие обязательной
  сущности — явно блокировать/сообщать, не подставлять молча.

## Процесс
- **Субагенты без явных конвенций** положили бизнес-логику в резолверы 5 из 8 доменов —
  полная переделка. Правило: в промпт субагента всегда вставлять `principles.md`.
- **Устаревший пункт ревью** («pgx-репозитории в домене — нарушение») относился к старой
  версии CLAUDE.md. Правило: перед исправлением находки ревью сверить её с текущими
  принципами.
