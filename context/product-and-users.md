# Продукт и пользователи

## Кто и зачем
«Вдвоём» (OurKoshelechek) — совместный бюджет для пары или небольшой группы/семьи
(N ≥ 2). Участники видят общие операции, делят расходы, планируют траты по категориям и
копят на цели. Мобильный сценарий в первую очередь (PWA, `InstallBanner`, нижний
`TabBar`, шторки `BottomSheet`). Один пользователь может состоять в нескольких группах.

## Словарь предметной области (зафиксированные решения)
- **Доход** (`INCOME`) — отдельный тип операции, **без категории** (`category_id = NULL`).
  Нет категорий вроде «Зарплата». Доход за период считается из транзакций автоматически.
- **Расход** (`EXPENSE`) — категория обязательна. Плательщик: один участник
  (`payer.mode = USER`) или разделение (`SPLIT`) — поровну между всеми N участниками или
  явными долями (`PayerShare`, сумма долей = сумма операции). В UI режим «Вместе»:
  вводишь долю одного — вторая подставляется как «общая сумма − первая».
- **Перевод** (`TRANSFER`) — между участниками: для отправителя расход, для получателя
  доход; на общий баланс и итоги группы не влияет. *(в работе, не закоммичено)*
- **Бюджет** — **план расходов по категориям** (`Category.monthlyLimit` на месяц).
  Не зависит от дохода, не требует планового дохода, валиден при доходе 0.
  Процент категории = потрачено / лимит категории, **не** от дохода.
  `Budget.income` — справочная сумма фактических доходов; `free = income − totalAllocated`
  (может быть < 0). Ручных «долей покрытия» между участниками нет — убраны.
- **Цель** — `SHARED` (взносы от нескольких) или `PERSONAL` (только от владельца-создателя;
  тип и владельца после создания не меняются). Текущая сумма считается из взносов, вручную
  не редактируется. Пополнение создаёт расход в служебной категории «Накопления» 💰
  (get-or-create по уникальному `(group_id, name)`); есть снятие с цели (`withdrawFromGoal`).
- **Удаление категории** не удаляет историю: транзакции отвязываются (`category_id = NULL`),
  `ON DELETE CASCADE` запрещён.
- **Период** — месяц `YYYY-MM` в `summary`/`budget`; произвольный диапазон дней
  `YYYY-MM-DD`–`YYYY-MM-DD` (обе границы включительно, UTC) — в `periodSummary`.
- **Деньги** — только рубли, целые копейки; мультивалютности нет.

## Роли и группы
`OWNER` (создатель) и `MEMBER`; на мутациях везде `@requireGroupRole(min: MEMBER)`.
Отличие одно: удалить участника можно только с ролью не ниже его (себя — всегда).
Роль `READER` есть в БД/домене, но не в GraphQL. Приглашение — по username, участник
добавляется сразу, без подтверждения. Email-инвайты заложены в схеме
(`group_invites`), но сервис возвращает `ErrEmailInviteNotSupported`.

## Экраны (`frontend/src/screens/`)
- **Auth** — логин/регистрация (username + пароль), access + refresh токены.
- **Overview** — баланс и его изменение за месяц, доходы по участникам, расходы по
  категориям и участникам, бюджет категорий с превышением, последние операции.
- **Transactions** — форма операции (тип, сумма, категория, плательщик, дата, комментарий),
  история с фильтром все/доходы/расходы, курсорная пагинация. API умеет фильтровать ещё
  по категории/участнику/датам — в UI не выведено.
- **Stats** (вкладка «Статистика») — выбор периода (7 дней / этот месяц / прошлый / свои
  даты), доходы и расходы, «кто сколько» по участникам, расходы по категориям с разбивкой
  по участникам (учитывает доли «Вместе»), список операций за период (до 500).
- **Budget** — лимиты категорий (инлайн-редактирование), добавление/удаление категорий,
  доход по участникам как справка.
- **Goals** — сводка (всего отложено, активных, за месяц), карточки целей с кнопками
  Пополнить (пресеты +5/10/25 тыс. и «Своя сумма») / Редактировать / Удалить.
- **Group** — список и переключение групп, создание, переименование, участники,
  приглашение, удаление участника, выход из аккаунта.

## Открытые продуктовые вопросы
1. Выводить ли `READER` в API и как его назначать?
2. Нужны ли email-инвайты и подтверждение приглашения приглашённым?
3. Нужны ли реальные различия прав `OWNER`/`MEMBER` (удаление группы, передача владения)?
4. Прогноз срока цели («ещё ≈ N мес.») — нужен ли и по какой формуле?
5. Повторяющиеся операции (аренда, подписки) — отдельная сущность или вручную?
6. Аудит правок операций?
7. Мультивалютность в будущем?
8. Смена пароля/username — экрана и API нет.
