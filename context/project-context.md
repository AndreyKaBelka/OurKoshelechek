## Открытые баги
- **Кнопка «Партнёр» без партнёра.** Если в группе нет второго участника, кнопка всё равно
  активна и молча записывает плательщиком текущего пользователя
  (`partner?.userId ?? currentUserId` в `TransactionsScreen.tsx`; то же в режиме «Вместе»
  и в переводах). Нужно решение владельца: блокировать/скрывать или предупреждать.

## Бэклог (по приоритету)
1. **Изображения для целей и категорий** — загрузка, показ в карточках/списках; эмодзи
   остаётся fallback. Хранилища файлов в проекте пока нет — сначала спроектировать.
2. **Отложенные транзакции:** фото чека → `DraftTransaction` (id, image, amount, date, note,
   createdAt) → позже «Создать транзакцию». Следующим шагом — OCR (сумма/дата/магазин →
   проверка пользователем). Зависит от хранилища файлов из п.1.
3. Редактирование названия/иконки категории (сейчас инлайн только лимит) — если понадобится.
4. Техдолг из code review:
   - `internal/service/*` работает с `graph/model` вместо доменных типов — большой
     рефакторинг, делать по одному сервису за раз, с ревью;
   - N+1 в `transaction.List`, `group.loadGroupModel`, списках целей;
   - `ErrNotFound` непоследовательно переводится в GraphQL-ошибку (`Update`/`Delete`).
5. Фильтры истории по категории/участнику/датам в UI (API уже умеет).
6. **Салют при пополнении цели** — после успешного пополнения накопительной цели показывать
   анимацию салюта/конфетти (фронтенд, без изменений API).
7. **Нормальное отображение ошибок на фронте** — сейчас ошибки GraphQL/сети показываются
   как есть или молча теряются; нужен единый механизм: понятные русские сообщения
   (маппинг кодов/`extensions` бэкенда), тосты или inline-ошибки в формах, отдельно —
   сетевые сбои и истёкшая сессия.
8. **Push-уведомления (Web Push) в PWA** — «партнёр добавил трату/перевод/пополнил цель», даже
   когда приложение закрыто. Работает на iOS 16.4+ для PWA с главного экрана (у нас так и
   установлено, `display: standalone`); разрешение — только по кнопке «Включить уведомления»
   внутри установленного приложения. Нужно: `sw.js` (с `no-cache` в nginx) + подписка
   `pushManager.subscribe` с VAPID; миграция `push_subscriptions`, мутации
   `subscribePush`/`unsubscribePush`, сервис отправки (`webpush-go`, VAPID-ключи в env),
   отправка всем участникам группы кроме автора, чистка подписок при 404/410. Открытый
   вопрос: о каких событиях уведомлять (всё или только траты и переводы).
